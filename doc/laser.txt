1. INTRODUCTION                                           *laser-introduction*

laser.nvim completes from the language servers attached to the buffer. There
are no separate completion sources to configure, and server priority is
customizable.

Suggestions stream into the menu as they arrive, so you can browse them
without waiting for every server or the full stream to finish. Once you start
navigating, visible candidates and your selection stay stable as more
suggestions arrive.

The same completion works on the command line, using LSP-powered suggestions
for `:` commands.

Requirements: Neovim 0.11 or newer and a configured LSP server that supports
completion.

==============================================================================
2. SETUP                                                         *laser-setup*

No setup function is required. Call |laser.complete()| when completion should
start or update, for example on every change in Insert mode:
>lua
  local group = vim.api.nvim_create_augroup("my-completion", { clear = true })

  vim.api.nvim_create_autocmd({ "InsertEnter", "TextChangedI" }, {
    group = group,
    callback = function()
      require("laser").complete()
    end,
  })
<
Then map keys to the |laser-actions|. Act on the menu while it is open;
otherwise keep the key's own behavior. The "i" flag of |nvim_feedkeys()| puts
the key where the mapped key was, ahead of keys typed after it.
>lua
  local laser = require("laser")
  local function map(key, action)
    vim.keymap.set({ "i", "c" }, key, function()
      if laser.visible() then
        action()
      else
        vim.api.nvim_feedkeys(vim.keycode(key), "in", false)
      end
    end)
  end
  map("<C-n>", function() laser.select(1) end)
  map("<C-p>", function() laser.select(-1) end)
  map("<C-y>", laser.confirm)
  map("<C-e>", laser.cancel)
<
                                                                *laser-manual*
For manual completion, replace the autocmd with a mapping:
>lua
  vim.keymap.set("i", "<C-Space>", function()
    require("laser").complete()
  end)
<
==============================================================================
3. ACTIONS                                                     *laser-actions*

Actions edit text and windows, so call them from regular mappings as in
|laser-setup|, not from |:map-<expr>| mappings. Each returns `false` when it
did nothing, so a mapping can fall back to the key's default behavior.

                                                              *laser-expr-map*
In an `<expr>` mapping, check |laser.visible()| and return a `<Cmd>` mapping:
>lua
  vim.keymap.set("i", "<Tab>", function()
    return laser.visible() and "<Cmd>lua require('laser').select(1)<CR>"
      or "<Tab>"
  end, { expr = true })
<
laser.select({delta}, {opts})                                 *laser.select()*
    Move the selection by {delta} and insert the selected candidate as you
    move. Pass `{ insert = false }` as {opts} to only highlight it.

    A candidate that would split the line, with a newline or by automatic
    wrapping, is only highlighted and is inserted when you confirm it.
    Single steps cycle back to what you typed, and larger steps, such as
    paging with `laser.select(10)`, stop at the first or last candidate.

laser.confirm()                                              *laser.confirm()*
    Accept the selected candidate. Returns `false` when nothing was selected,
    and closes the menu either way.

    Confirming applies the server's edits for the candidate, including edits
    elsewhere in the buffer such as imports. When a server provides those
    only on request, confirming waits for them for up to a second. In Insert
    mode, snippets expand with |vim.snippet.expand()|; on the command line,
    their text is inserted without tabstops.

laser.cancel()                                                *laser.cancel()*
    Restore the typed input and close the menu.

laser.close()                                                  *laser.close()*
    Close the menu and stop pending requests without restoring the typed
    text.

laser.select_mouse()                                    *laser.select_mouse()*
    Select the candidate under the mouse. Returns `false` outside the menu.
>lua
    vim.keymap.set("i", "<LeftMouse>", function()
      if not laser.select_mouse() then
        vim.api.nvim_feedkeys(vim.keycode("<LeftMouse>"), "in", false)
      end
    end)
<
laser.scroll_preview({delta})                         *laser.scroll_preview()*
    Scroll the |laser-preview| by {delta} lines; negative scrolls up.

laser.toggle_preview()                                *laser.toggle_preview()*
    Hide or show the |laser-preview|.

laser.visible()                                              *laser.visible()*
    Whether the menu is open.

4. OPTIONS                                                     *laser-options*

laser.complete({opts})                                      *laser.complete()*
    Start or update completion at the current cursor. Options belong to this
    call, so pass them from your completion callback. They also apply to
    results already received. {opts} is a table with these optional keys:

    clients ~
        (string[]) Client names in display order. See |laser-clients|.
        Default: every attached client that supports completion.
    clientOptions ~
        (table) Options per client. See |laser-clientOptions|.
    enable_commit_characters ~
        (boolean) Default: `false`. See |laser-enable_commit_characters|.
    menu ~
        (table) The built-in menu. See |laser-menu|.
    language_id ~
        (string) Filetype of the scratch document in command-line mode. See
        |laser-cmdline|.

                                                               *laser-clients*
In your completion callback, choose servers and their display order:
>lua
  require("laser").complete({
    -- Show lua_ls first, then other attached clients.
    clients = { "lua_ls", "*" },
    clientOptions = {
      -- Every client: optional request timeout in milliseconds.
      _ = { timeout_ms = 1000 },
      copilot = { enabled = false },
    },
  })
<
Omit `clients` to use all attached completion clients, or list names without
`"*"` to use only those clients. In `clients`, `"*"` stands for every attached
client the list does not name. Requests have no timeout by default.

                                                         *laser-clientOptions*
`clientOptions` is resolved per client, key by key:

- `clientOptions._` holds defaults every client inherits.
- `clientOptions[name]` overrides them for that client.
- `clientOptions["*"]` applies, over `_`, only to clients without an entry of
  their own.

So `{ ["*"] = { enabled = false }, lua_ls = {} }` requests completion from
lua_ls alone, while `{ _ = { enabled = false } }` disables every client that
does not set `enabled = true` itself.

Each client accepts:

    enabled ~
        (boolean) `false` skips the client.
    timeout_ms ~
        (integer) Request timeout in milliseconds. `nil` or `0` disables it.
    max_items ~
        (integer) See |laser-max_items|.
    filters ~
        (table[]) Matchers, sorters and converters. See |laser-filters|.
    matcher ~
        (function) Older alternative to `filters`. See |laser-filters|.
    sorter ~
        (function) Older alternative to `filters`. See |laser-filters|.
    refresh ~
        (function) When to request again. See |laser-refresh|.

                                                             *laser-max_items*
Set `clientOptions[name].max_items = 30` to display at most 30 candidates from
that client after filtering and sorting. Use `clientOptions._.max_items = 30`
to apply the limit to each client by default; individual clients can override
it. Cached results remain available for further narrowing, and converters
after the last matcher or sorter run only on the displayed candidates. Omit it
or use `0` for no limit.

                                              *laser-enable_commit_characters*
To accept the selected suggestion when you type a server-defined commit
character, then insert that character (disabled by default):
>lua
  require("laser").complete({ enable_commit_characters = true })
<

5. COMMAND-LINE COMPLETION                                     *laser-cmdline*

Enable an LSP server for the `vim` filetype with |vim.lsp.enable()|, then add:
>lua
  vim.api.nvim_create_autocmd({ "CmdlineEnter", "CmdlineChanged" }, {
    pattern = ":",
    callback = function()
      require("laser").complete({ language_id = "vim" })
    end,
  })
<
The mappings in |laser-setup| work in both Insert and command-line mode.

==============================================================================
6. MENU                                                           *laser-menu*

Pass `menu` to adjust the built-in menu:
>lua
  require("laser").complete({
    menu = {
      max_height = 10, -- Rows shown at once; defaults to 'pumheight' or 10.
      max_width = 80,
      border = "none",
      auto_select = false, -- Highlight the first candidate without inserting.
      direction = "auto", -- "auto", "below", or "above".
      reversed = false, -- List bottom-up when the menu opens above.
    },
  })
<
`border` takes any value of the `border` option of |nvim_open_win()|. With
`direction = "auto"`, the menu opens below unless the rows do not fit there
and above has more room. The command-line menu always opens above.

When the server preselects candidates, the first one is highlighted without
being inserted, whether or not `auto_select` is set.

The menu draws only the rows in view. Filtering and column widths still visit
every candidate, so |laser-max_items| remains useful for servers that return
very long lists.

                                                             *laser-highlight*
The menu uses |hl-Pmenu|, |hl-PmenuSel|, |hl-PmenuKind|, |hl-PmenuKindSel|,
|hl-PmenuExtra|, |hl-PmenuExtraSel|, |hl-PmenuSbar| and |hl-PmenuThumb|, like
the built-in popup menu.

==============================================================================
7. DOCUMENTATION PREVIEW                                       *laser-preview*

Show documentation for the selected candidate beside the menu:
>lua
  require("laser").complete({
    menu = {
      preview = { border = "single", max_width = 60, max_height = 20 },
    },
  })
<
Use `preview = true` for the defaults. Map |laser.scroll_preview()| and
|laser.toggle_preview()| to scroll or toggle the preview.

8. MATCHING AND HIGHLIGHTING                                  *laser-matching*

Fuzzy matching and score sorting are enabled by default. Equal scores follow
the server's `sortText`, then the label, so an empty input shows the server's
ranking. The menu highlights the matched characters with |hl-PmenuMatch|
(|hl-PmenuMatchSel| on the selected row). Matchers in `filters` get the same
highlighting when their match info includes `positions`; the older `matcher`
option returns only a score. Link `PmenuMatch` and `PmenuMatchSel` to `Pmenu`
and `PmenuSel` to turn it off.

Converters in your filters may add their own `highlights`, and the menu draws
them. Each entry is
>lua
  { type = "abbr"|"kind"|"menu", col = 1, width = 3, hl_group = "Special" }
<
where `col` is the 1-based byte column in that field and `width` its length
in bytes. `require("laser.filter").highlight_converter()` computes the match
highlights for every displayed candidate in advance; the menu then uses those
instead of its own.

                                                               *laser-filters*
Customize matching and sorting per client with `filters`, a list run in
order. Each entry is a table with `kind` and `callback`:
>lua
  local filter = require("laser.filter")
  require("laser").complete({
    clientOptions = {
      _ = {
        filters = {
          { kind = "matcher", callback = filter.fuzzy_matcher() },
          { kind = "sorter", callback = filter.by_score },
          { kind = "converter", callback = filter.highlight_converter() },
        },
      },
    },
  })
<
An empty list keeps the server's order and every candidate. When `filters`
is set, the older `matcher` and `sorter` options are ignored.

A candidate is a |complete-items| table: `word`, `abbr`, `kind` and `menu`,
plus `user_data.laser` with `item` (the LSP CompletionItem), `client_id` and,
after a matcher, `match_info`.

    matcher ~
        `fun(input, candidate): boolean, info?`
        Return `false` to drop the candidate, or `true` and a match info
        `{ score = number, positions? = integer[] }`. `positions` are 0-based
        character indices into `item.filterText` or `item.label`, and enable
        match highlighting. Matchers must not modify the candidate.
    sorter ~
        `fun(a, b): boolean`
        A comparator for |table.sort()|. Candidates it considers equal keep
        their order.
    converter ~
        `fun(candidate, input): candidate`
        Return the candidate to display. A converter owns the candidate, its
        `user_data.laser`, and the top-level fields of `item`. Replace nested
        tables of `item` instead of mutating them; they are shared with the
        cache.

The older `matcher` option is `fun(input, candidate): number?`, returning a
score or `nil` to drop the candidate. `sorter` is a comparator as above.

                                                *laser.filter.fuzzy_matcher()*
filter.fuzzy_matcher()
    The default matcher: fuzzy matching against `item.filterText`, or
    `item.label`, with |matchfuzzypos()|.

filter.by_score                                        *laser.filter.by_score*
    The default sorter: higher score first, then |laser.filter.by_sort_text|.

                                                 *laser.filter.score_sorter()*
filter.score_sorter({opts})
    Create a sorter by descending score. Equal scores keep their order, or
    are ordered by `opts.tiebreak`, a sorter, when given.

filter.by_sort_text                                *laser.filter.by_sort_text*
    A sorter by the server's `sortText`, falling back to the label, as the
    LSP specifies.

                                          *laser.filter.highlight_converter()*
filter.highlight_converter()
    Create a converter that stores match highlights on every candidate it
    converts. See above.

9. REFRESH                                                     *laser-refresh*

Laser filters cached results as you type and asks a client again only when
its `refresh` callback returns `true`. A new completion range, such as a new
word, always requests fresh results.

By default, edits that no longer retain the previous input as a prefix
trigger a background refresh, even when cached candidates still match. So
does a request that was cancelled, timed out or failed, which a refresh
callback sees as `ctx.interrupted`. The menu keeps matching cached candidates
until the new response replaces that client's results. Custom refresh
callbacks can use `require("laser.refresh").extendsPreviousInput(ctx)` to
make the same comparison; identical input counts as extending the previous
input.

For example, to also refresh after a dot:
>lua
  local refresh = require("laser.refresh")
  require("laser").complete({
    clientOptions = {
      _ = {
        refresh = function(ctx)
          return refresh.default(ctx) or refresh.hasPattern(ctx, "%.$")
        end,
      },
    },
  })
<
                                                       *laser-refresh-context*
The callback receives a context with these fields:

    client_id, client_name ~
        The client to request from.
    bufnr ~
        The completion document; a scratch buffer in command-line mode.
    mode ~
        `"i"` or `"c"`.
    before_cursor ~
        The current line up to the cursor.
    previous_before_cursor ~
        The previous line up to the cursor, when available.
    inserted_char ~
        The single inserted character, or `""` for other changes.
    trigger_characters ~
        This client's trigger characters.
    is_incomplete ~
        Whether the last response was incomplete; `nil` until one arrives.
    has_candidate ~
        Whether this client has candidates for the current input.
    pending ~
        Whether this client has a request in flight.
    timed_out ~
        Whether the last request timed out.
    interrupted ~
        Whether the last request was cancelled, timed out or failed before
        its final answer.

refresh.default({ctx})                               *laser.refresh.default()*
    The default callback. Returns `true` when the last request timed out or
    was interrupted, the last response was incomplete, a trigger character
    was typed, the input no longer extends the previous input, or nothing is
    pending and no candidate matches.

refresh.hasTriggerCharacter({ctx})       *laser.refresh.hasTriggerCharacter()*
    Whether the inserted character is one of the client's trigger
    characters.

refresh.hasPattern({ctx}, {pattern})              *laser.refresh.hasPattern()*
    Whether the line before the cursor matches the Lua {pattern}. Use `$` to
    anchor it at the cursor. Deletions and other changes can match too.

refresh.has_candidate({ctx})                   *laser.refresh.has_candidate()*
    Whether this client has candidates for the current input.

refresh.extendsPreviousInput({ctx})     *laser.refresh.extendsPreviousInput()*
    Whether the current input keeps the previous input as a prefix.
    Identical inputs count; a missing previous input does not. This compares
    text, not edits or candidates.
